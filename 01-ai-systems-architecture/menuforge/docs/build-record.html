The live call actually worked

A synthetic menu image goes to the real API with extraction unpatched. Claude returned all six dishes with prices transcribed exactly — 4.50, 3.25, 12.50, 11.00, 2.80, 3.00. The price assertion is exact equality, not a tolerance.

What this still will not do

Accepted limits, not oversights. The first four are out of scope by PRD §5; the rest are consequences reasoned through in DECISIONS.

  • No auth and no rate limiting. Anyone who can reach the endpoint can spend your API budget.
  • No job queue. The Claude call runs on the request thread, so client latency equals model latency.
  • No vector search, no frontend, no multi-tenancy.
  • No migrations. create_all() cannot alter a populated table — the first schema change against real data has no upgrade path. D-002 names this as the first thing to fall.
  • Uploads always append. Re-uploading the same menu duplicates rows.
  • The image is discarded after the call, so a failed extraction cannot be replayed or reviewed.
  • A 200 is not an accuracy guarantee. It means the response validated, not that the model read the menu correctly.
